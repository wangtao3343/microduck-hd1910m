# 语音对话：本机模型怎么装，鸭子怎么连

这份文档写给以后自己操作的人：**主机上要跑什么、怎么起、怎么验证；板子上怎么配、怎么重启、出问题看哪里。**

设计背景见 [语音交互方案.md](语音交互方案.md)，指令（停下/坐下/前进/叫一声）的实现说明见
[microduck/docs/design/voice-control.md](../microduck/docs/design/voice-control.md)。
本文只讲操作。

## 为什么分两台机器

```
板子 duck-ear                         主机（你的工作机 192.168.3.11）
  麦克风 → VAD 分句 → SenseVoice 识别
        │  文本（走 LAN，不上互联网）
        └────────────→ Ollama :11434  qwen3.5:9b   ← 大脑，约 2 秒
        ←──────────── 回答文本
        └────────────→ serve_f5.py :8100  F5-TTS 克隆提示音 ← 嗓子，约 1–2 秒
        ←──────────── WAV
  喇叭播放（播放时麦克风不读）
```

板子是 4×A55、2 GB 内存，能听能说，跑不动值得对话的模型。实测：

| 任务 | 板子上 | 主机上 |
|---|---|---|
| 听（SenseVoice int8） | RTF 0.39，可用 | — |
| 说（VITS fanchen-C） | **RTF 8.8–13，不可用**（2 秒的话要合成 19 秒） | RTF 0.4，可用 |
| 说（MeloTTS，备选） | 没试过，只会更慢 | RTF 0.19–0.29（8 线程） |
| 说（F5-TTS 克隆，**默认**） | 要 GPU，跑不了 | RTF 约 0.4（3060，4.6 秒的话合 2.3 秒） |
| 想（qwen3.5:9b） | 跑不了 | 预热后约 2 秒 |

所以听留在板子上，想和说放主机。**主机关机或断网时，指令照常能用，只是不会对话。**

# 一、主机：模型和服务

## 1.1 Ollama（大脑）

### 现状（已经装好了）

| 项 | 值 |
|---|---|
| 版本 | ollama 0.32.5 |
| 服务 | systemd 系统服务 `/etc/systemd/system/ollama.service`，已 enabled |
| 监听 | `0.0.0.0:11434`（单元里有 `Environment="OLLAMA_HOST=0.0.0.0"`，局域网能访问） |
| 用户 | `ollama` |

检查：

```bash
systemctl status ollama --no-pager      # Active: active (running)
curl -s http://127.0.0.1:11434/api/tags | head -c 300
```

`~/start_ollama_qwen.sh` 是**交互式命令行**，和后台服务无关。服务已经把模型加载在内存里时，
不需要跑这个脚本；它只适合手动聊天的场合。脚本当前内容是 `ollama run qwen2.5-coder:7b`。

### 选哪个模型（实测）

同一台机器、同样的请求（约 40–50 个 token）：

| 模型 | 体积 | 预热后耗时 | 速度 | 结论 |
|---|---|---|---|---|
| **qwen3.5:9b** | 6.6 GB | **1.9–2.8 s** | ~45 token/s | **用它** |
| gemma4:12b | 7.6 GB | 2.75 s | 32 token/s | 可用，中文稍逊 |
| qwen2.5-coder:14b | 9 GB | 1.87 s | 30 token/s | 代码用，聊天不必要 |
| qwen3.5:27b | 17 GB | **14.9 s** | 3.8 token/s | **语音场景不可用**，别选 |

语音的要求是"答完一句话之前人还没走"，2 秒可以接受，15 秒不行——所以默认 `qwen3.5:9b`。

### 装一个新模型（以后换模型时）

```bash
ollama pull qwen3.5:9b
ollama list
```

国内拉取慢可以换源（可选，只影响下载）：

```bash
export OLLAMA_MODELS="$HOME/.ollama/models"   # 模型目录，默认就是这里
```

### 验证接口

```bash
curl -s http://127.0.0.1:11434/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.5:9b",
       "messages":[{"role":"user","content":"用一句话介绍你自己"}],
       "stream":false,"think":false,"keep_alive":"30m"}' \
  | head -c 400
```

回答在 `message.content` 里。鸭子发的请求和这一条相同，多了 `options.num_predict: 120`
（限制长度，回答会朗读出来，不要长篇）。

三个参数为什么这样：

- `"stream": false` —— 鸭子要整句才能合成，逐 token 没有用处。
- `"think": false` —— qwen3.5 默认会"先想"，想的内容没人听，白白多等好几秒。
- `"keep_alive": "30m"` —— Ollama 默认空闲 5 分钟就把模型卸掉，下一句又要等 5–8 秒加载。
  30 分钟让对话中间的停顿保持热。

## 1.2 TTS 服务（嗓子）

### 目录

```
tools/duck-tts/          仓库里的目录（服务本身进 git，模型和 venv 不进）
  .venv-f5/              Python 3.12 + torch 2.15(CUDA) + f5-tts 1.1.22 —— 现在跑的是这个
  .venv/                 Python 3.12 + sherpa-onnx 2.0.1 + numpy 2.5.4 —— 备选方案用
  models/
    f5/
      ref_fault_reset.wav  参考音：机器人提示音「伺服故障已复位，请按开始键继续」，
                           24 kHz 单声道，4.06 秒（F5 克隆的就是这个人的声音）
      ref_relax.wav        另一个参考音「我累了，休息一下」，2.3 秒（备选，音色更放松）
    melo/                MeloTTS 中文+英文，44.1 kHz，自然女声（183 MB，备选）
      model.onnx         fp32；int8 在这颗 Xeon 上慢 10 倍，不要用
    fanchen/             VITS vits-zh-hf-fanchen-C，16 kHz，偏动漫（132 MB，备选）
  serve_f5.py            **默认服务**：F5-TTS 克隆提示音，GET /say?text=… 返回单声道 WAV
  serve.py               备选服务：sherpa-onnx 的 melo / fanchen，同一个 HTTP 接口
  requirements-f5.txt  requirements.txt
  README.md
  f5.log  serve.log
```

两个脚本都用自己所在目录找模型，所以仓库挪到哪都能跑；`.venv*/` 和 `models/` 在本机生成，
`.gitignore` 已经排除。两者输出都会做峰值归一化（0.85）：模型本身很轻（峰值 0.1–0.2），
鸭子的小喇叭听不清。

**为什么用 F5-TTS 而不是现成的音库**：你要的是「开机提示音那种」——那是提示音库里真人录的
声音，任何预训练音色都对不上。F5 是零样本克隆：给 4 秒参考音 + 它的文字，就能用这个人的
嗓音说新句子。权重不训练、不修改。

**为什么降 2 个半音**（`F5_PITCH=0.891`）：克隆出来比原声高，降 2 个半音才落回提示音那个位置。
降调用 ffmpeg 的 `rubberband`，只改音高不改时长，一句话多几十毫秒；它会把电平压掉约 10%，
所以归一化放在降调之后。`F5_PITCH=1` 关掉降调。

### 换声音 / 换参考音

```bash
nohup .venv-f5/bin/python serve_f5.py > f5.log 2>&1 &        # 默认（克隆 + 降 2 半音）
F5_PITCH=1 nohup .venv-f5/bin/python serve_f5.py > f5.log 2>&1 &   # 不降调
F5_REF=models/f5/ref_relax.wav F5_REF_TEXT=我累了，休息一下 \
  nohup .venv-f5/bin/python serve_f5.py > f5.log 2>&1 &      # 换参考音（文字必须和录音一致）

# 备选：sherpa-onnx 的两套（不要和上面同时占 8100）
nohup .venv/bin/python serve.py > serve.log 2>&1 &           # melo
DUCK_TTS_VOICE=fanchen nohup .venv/bin/python serve.py > serve.log 2>&1 &
```

两个服务的 HTTP 接口完全一样，鸭子那边不用改。**8100 只能有一个进程**，换之前先
`pkill -f serve_f5.py` 或 `pkill -f serve.py`。

### 从零重装（默认的克隆方案）

需要 NVIDIA 显卡（实测 3060 12 GB，和 Ollama 并存）。权重不进仓库，第一次启动自动下。

```bash
cd /home/ai/microduck-hd1910m/tools/duck-tts

# 运行环境：单独的 venv，torch + CUDA 那一套和 .venv 里的 sherpa-onnx 不能混
uv venv .venv-f5 --python 3.12
uv pip install --python .venv-f5/bin/python \
  --index-url https://pypi.tuna.tsinghua.edu.cn/simple \
  -r requirements-f5.txt

# 参考音：提示音库在板子上，不在仓库里，抓回来降到 24 kHz 单声道
mkdir -p models/f5
scp duck@192.168.3.10:/var/lib/robot/prompts/fault_reset.wav /tmp/
ffmpeg -y -i /tmp/fault_reset.wav -ac 1 -ar 24000 models/f5/ref_fault_reset.wav
scp duck@192.168.3.10:/var/lib/robot/prompts/relax.wav /tmp/
ffmpeg -y -i /tmp/relax.wav -ac 1 -ar 24000 models/f5/ref_relax.wav

.venv-f5/bin/python serve_f5.py --check     # 首跑下 ~1.4 GB 权重（脚本里已设 hf-mirror）
```

权重进 `~/.cache/huggingface/hub`（约 1.4 GB：`F5TTS_v1_Base` 1.3 GB + vocos 声码器），
**不在 `models/` 里**，删项目目录不会带走它们。参考音的文字必须和录音一字不差，
`serve_f5.py` 的 `REF_TEXT` 就是给它做条件的。

### 从零重装（备选的 melo / fanchen）

```bash
cd /home/ai/microduck-hd1910m/tools/duck-tts
mkdir -p models/melo

B=https://hf-mirror.com/csukuangfj/vits-melo-tts-zh_en/resolve/main
for f in model.onnx tokens.txt lexicon.txt date.fst number.fst phone.fst \
         new_heteronym.fst dict/hmm_model.utf8 dict/idf.utf8 dict/jieba.dict.utf8 \
         dict/stop_words.utf8 dict/user.dict.utf8 dict/pos_dict/char_state_tab.utf8 \
         dict/pos_dict/prob_emit.utf8 dict/pos_dict/prob_start.utf8 dict/pos_dict/prob_trans.utf8; do
  mkdir -p "models/melo/$(dirname "$f")"
  curl -sL -o "models/melo/$f" "$B/$f"
done

# 备选：fanchen-C（119 MB 压缩包）
curl -LO https://github.com/k2-fsa/sherpa-onnx/releases/download/tts-models/vits-zh-hf-fanchen-C.tar.bz2
tar xjf vits-zh-hf-fanchen-C.tar.bz2
mkdir -p models/fanchen && mv vits-zh-hf-fanchen-C/* models/fanchen/

# 运行环境（用 uv；PyPI 慢的时候加清华镜像）
uv venv .venv
uv pip install --python .venv/bin/python \
  --index-url https://pypi.tuna.tsinghua.edu.cn/simple \
  -r requirements.txt
```

没有 uv 的话，普通 venv 也可以：`python3 -m venv .venv && .venv/bin/pip install sherpa-onnx numpy`。

### 开机自启（可选，推荐）

Ollama 已经是系统服务，TTS 还没有。用用户级单元：

```bash
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/duck-tts.service <<'EOF'
[Unit]
Description=Duck TTS (F5-TTS voice clone on HTTP :8100)
After=network-online.target

[Service]
WorkingDirectory=/home/ai/microduck-hd1910m/tools/duck-tts
ExecStart=/home/ai/microduck-hd1910m/tools/duck-tts/.venv-f5/bin/python serve_f5.py
Restart=always
RestartSec=3

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user enable --now duck-tts
sudo loginctl enable-linger ai     # 没登录也运行（这一条要 sudo）
```

检查：`systemctl --user status duck-tts`，`journalctl --user -u duck-tts -f`。

> 手动 nohup 起的进程和这个单元**不能同时存在**：8100 端口只有一个。启用单元前先
> `pkill -f serve_f5.py`。单元里没有显卡相关的特权设置——用户在自己会话里能直接用
> `/dev/nvidia*`，不需要额外授权。

# 二、板子：鸭子怎么连

## 2.1 新增的命令行参数

`duck-ear` 的默认值已经指向主机的 192.168.3.11，正常情况下**不用改 systemd 单元**。

| 参数 | 默认值 | 作用 |
|---|---|---|
| `--brain` | `192.168.3.11:11434` | Ollama 地址；设成 `""` 关闭对话（只留指令） |
| `--brain-model` | `qwen3.5:9b` | 问哪个模型 |
| `--tts` | `192.168.3.11:8100` | TTS 服务地址；设成 `""` 时回答只写日志不朗读 |
| `--speaker` | `plughw:aic3104,0` | 放音设备（和提示音同一个 codec 输出） |

`--dry-run` 仍然只拦 robotd：不动作、不叫，但**照常对话和说话**，用来测试语音链路。
只想测识别不动嘴时：`duck-ear --dry-run --brain "" --tts ""`。

## 2.2 它怎么判断一句话

```
识别出一句文本
  ├─ 是指令（停下/坐下/前进/叫一声…）        → 本地执行，< 1 秒，永远优先
  ├─ 含「小鸭」「小鸭子」「鸭鸭」「鸭子」      → 当成对鸭子说的话，去掉名字后送去对话
  ├─ 上一条回答后 45 秒内                    → 也当成对话（不用每次喊名字）
  └─ 其他                                    → 只记一行 "not a command"
```

- **指令优先**："小鸭坐下" 是坐下，不是问句。
- 只喊名字（"小鸭？"）不调用模型，直接说「我在。」
- 45 秒窗口是为了能连续聊天；代价是这期间房间里别的话也会被回答。
- 对话期间麦克风不读（鸭子听不到自己说的话），说完再静音 0.6 秒丢弃残留。
- **连不上主机时会开口**：大脑没回应 → 说「我连不上电脑了，请检查一下。」；嗓子（TTS）也一起
  挂了（两台服务在同一台机器上，通常一起挂）→ 放这句**预先合成好、编进二进制**的录音
  （`duck-ear/assets/host_offline.wav`，2.9 秒，就是鸭子自己的音色），不依赖主机。
  万一连录音都放不出来，才退到最后一步：一声**尖锐的报警音**（不是指令的「嘎」）。
  所以听到这句话 = 主机/网络有问题，不是鸭子没听见。

## 2.3 部署新二进制（要 sudo，需要密码）

二进制换了，服务要先停再换（运行中的文件不能直接覆盖）：

```bash
cd /home/duck/workspace/microduck-hd1910m/out/arm64/bin
sudo systemctl stop duck-ear
mv duck-ear.new duck-ear
sync
sudo systemctl start duck-ear
```

看日志：

```bash
journalctl -u duck-ear -f
# 正常启动：
#   加载 ASR / VAD → remarks go to at=192.168.3.11:11434 model=qwen3.5:9b
#   the brain is warm
#   listening — say 停下, 坐下, 前进 or 叫一声; say 小鸭 to talk
```

启动约 25 秒（加载 240 MB 的 SenseVoice）。`the brain is warm` 说明主机已经接上；
没接上会打印 `the brain is not answering yet`，不影响听指令。

## 2.4 改地址（主机 IP 变了才需要）

主机的 `192.168.3.11` 是无线网卡上的 DHCP 地址，**有可能会变**。变了以后鸭子的回答会全部失败
（指令不受影响）。改法二选一：

```bash
# 临时：手动跑
/home/duck/workspace/microduck-hd1910m/out/arm64/bin/duck-ear --dry-run \
  --socket /home/duck/workspace/microduck-hd1910m/local/robotd.sock \
  --brain 192.168.3.20:11434 --tts 192.168.3.20:8100
```

```bash
# 永久：覆盖单元
sudo systemctl edit duck-ear
# 写入：
# [Service]
# ExecStart=
# ExecStart=/home/duck/workspace/microduck-hd1910m/out/arm64/bin/duck-ear \
#     --socket /home/duck/workspace/microduck-hd1910m/local/robotd.sock \
#     --brain 192.168.3.20:11434 --tts 192.168.3.20:8100
sudo systemctl daemon-reload && sudo systemctl restart duck-ear
```

以后如果给主机在路由器上做静态 DHCP，地址就不变了。

# 三、验证清单

按顺序做，一步一步排除：

```bash
# 1. 主机上两个服务活着
curl -s http://192.168.3.11:11434/api/tags  | head -c 100   # {"models":[...]
curl -s http://192.168.3.11:8100/health                     # ok

# 2. 板子能访问主机（在板子上执行；上面两条换成 192.168.3.11 一样跑一遍）

# 3. 板子的喇叭能放合成语音（在板子上执行）
curl -s -o /tmp/t.wav 'http://192.168.3.11:8100/say?text=你好，我是小鸭。'
aplay -D plughw:aic3104,0 /tmp/t.wav

# 4. 完整链路：对着鸭子说「小鸭，你好」
journalctl -u duck-ear -f
#   听到 → segment decoded seconds=… decode_ms=…
#   回答 → heard=小鸭你好  remark=你好  took_ms=…  reply=…
#   播放 → 喇叭出声；之后 0.6 秒内的声音不会进识别
```

3 过了但 4 没反应，说明问题在识别或唤醒词；4 里 `answered` 有、但没声音，说明 `aplay` 或设备。

# 四、故障排查

| 现象 | 先看 | 原因 / 处理 |
|---|---|---|
| 说话完全没反应 | `journalctl -u duck-ear -n 50` | 服务没起（`systemctl status duck-ear`）；有 `heard=` 但不认识 → 正常，只记日志 |
| 有 `heard=…` 但不回答 | 文本里有没有「小鸭」 | 没有唤醒词又不在 45 秒窗口内，就不对话；喊一声「小鸭」 |
| 回答了但没声音 | `curl …8100/health`、`aplay` 直接放 | TTS 没起、主机 IP 变了、喇叭被占用（看 `fuser /dev/snd/*`） |
| 鸭子说「**我连不上电脑了**」或吹报警音 | 日志 `the brain did not answer` / `the reply was not spoken` | 连不上主机：Ollama / TTS 没起、主机 IP 变了、断网。指令不受影响 |
| 日志 `the brain did not answer` | 主机 `systemctl status ollama` | Ollama 没起 / IP 变了 / 防火墙挡 11434 |
| 回答很慢（> 10 秒） | 主机 `ollama ps` | 用了 27b，或模型被卸载后在冷加载；换 `qwen3.5:9b`，确认 `keep_alive` 30m |
| 鸭子把自己的声音听进去 | 日志里出现自己刚说过的话 | 正常不该发生（播放期间不读麦克风、之后静音 0.6 秒）；若出现，检查是否 `robotd` 自己放的提示音（那种不在静音窗口内） |
| TTS 报 400/413 | `f5.log` | 空文本或超过 300 字；模型回复太长时鸭子已按 120 token 截断 |
| 启动打印 `device=cpu`，合成一句要几十秒 | `nvidia-smi` | 显卡没被 torch 用上；把 `F5_DEVICE=cuda` 显式设上，或检查 CUDA 版本和驱动 |
| `CUDA out of memory` | `nvidia-smi` | Ollama 之外又占了别的卡；停掉多余的进程，或 `F5_DEVICE=cpu` 应急（会很慢） |
| 合成出来不像提示音 | `models/f5/ref_fault_reset.wav` | 参考音被换过 / 不是 24 kHz 单声道 / `F5_REF_TEXT` 和录音对不上；重抓重转一次 |
| 声音太高或太低 | `f5.log` 里的 `pitch=` | `F5_PITCH` 现在 0.891（降 2 个半音）；1.0 不降，0.944 降 1 个 |
| 板子温度高 | `cat /sys/class/thermal/thermal_zone0/temp` | 对话时多的是主机，板子上只有 VAD（约 9.5% 一个核）+ 每句解码 |

# 五、数字与隐私

- 板子：常驻 VAD 约 9.5% 一个核，RSS 607 MB，单句解码 RTF 0.39（2 线程）。
- 端到端：说完 → VAD 等 0.5 秒静音 → 解码 0.4–0.8 秒 → 模型 2 秒 → 合成 1–2.5 秒 →
  开始出声。**大约 5–6 秒**（克隆比 melo 慢约 1 秒，换来的是像提示音）；要做更快就得让
  模型流式出、合成分段，目前没做。合成耗时随句子长度走，4.6 秒的话约 2.3 秒。
- 隐私：**麦克风录的音频不出板子**。发给主机的是识别后的文字（走局域网，不经过互联网），
  主机回传的是合成的 WAV。主机和板子之间没有第三方服务。
