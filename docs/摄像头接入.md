# 摄像头接入（Radxa Camera 8M / IMX219 ↔ Radxa Zero 3W）

**2026-11-01：硬件链通了，`mediad` 也部署了。** 驱动 probe、ISP、取流、出图全部验证过；
曝光的闭环在 `mediad::exposure` 里，当天装机后开机不再是黑图（见文末那一节）。
只手动起 `v4l2-ctl` 取流而不跑 `mediad` 时，仍然是黑图 —— 传感器停在驱动默认曝光。
上游的设计依据在 `microduck/docs/project/media-bringup.md`；本文只记这一支的实际结论。

## 做了什么

### 1. 启用 overlay

没有 overlay 时，CSI 摄像头**不产生 `/dev/video*`、dmesg 里也一个字都没有**，
和「摄像头根本没插」现象完全一样。板上 overlay 文件本来就在：

```
/boot/dtb/rockchip/overlay/rk3568-radxa-zero3-rpi-camera-v2.dtbo
```

把它追加到 `extlinux.conf` 的 `fdtoverlays` 行（先备份；重复执行不会加两次）：

```bash
sudo bash -c 'f=/boot/extlinux/extlinux.conf; b="$f.bak-$(date +%Y%m%d-%H%M%S)"; cp -a "$f" "$b" || exit 1; grep -q rk3568-radxa-zero3-rpi-camera-v2 "$f" || sed -i "/^  fdtoverlays /s|\$| /boot/dtb/rockchip/overlay/rk3568-radxa-zero3-rpi-camera-v2.dtbo|" "$f"; sync; echo "backup: $b"; grep fdtoverlays "$f"'
```

然后 `sudo reboot`。本次的备份是 `extlinux.conf.bak-20261101-212135`。

### 2. 重启后确认

```bash
dmesg | grep -iE "imx219|rkisp|csi2"
```

应该看到（本次实测）：

```
imx219 2-0010: driver version: 00.01.01
imx219 2-0010: Model ID 0x0219, Lot ID 0x5b6a82, Chip ID 0x0690
rockchip-csi2-dphy csi2-dphy0: dphy0 matches m00_b_imx219 2-0010:bus type 5
rkisp-vir0: Async subdev notifier completed
```

`Model ID 0x0219` 是传感器**真实应答**的证据 —— 排线反了/没插会是
`Reading register 100 from 10 failed` 或 error -5。

```bash
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video0 --list-formats-ext
```

`/dev/video0` 的格式应该到 1920×1080；如果只有 800×600 之类的兜底格式，
说明 sensor 没在应答（回到排线问题）。

### 3. 出一帧

```bash
gst-launch-1.0 -q v4l2src device=/dev/video0 num-buffers=30 \
  ! video/x-raw,format=NV12,width=1280,height=720,framerate=30/1 \
  ! videoconvert ! jpegenc ! multifilesink location=/tmp/cam-%03d.jpg
```

## 坑

### 开机黑图：没人写曝光

`setup-rkaiq.sh` 显式把 rkaiq 的 AE 关掉（`CommCtrl.Enable = 0`），理由是它的 AE
**只在 stream start 时收敛一次**，之后不再跟随场景变化；曝光的持续闭环由
`mediad::exposure` 负责（见 `microduck/docs/project/media-bringup.md`
的 "rkaiq's auto-exposure fires once" 一节）。

现在 `mediad` 没部署，所以传感器一直停在 boot 值，画面几乎全黑。
**这跟摄像头没插/排线反了长得一模一样**，别再从硬件查起。临时看画面：

```bash
# 先起流，再写曝光（顺序无所谓，但必须在流里看效果）
v4l2-ctl -d /dev/v4l-subdev2 --set-ctrl exposure=3000
v4l2-ctl -d /dev/v4l-subdev2 --set-ctrl analogue_gain=2816   # 上限就是 2816（≈11×）
```

本次实测这样写完之后画面立刻正常（拍的是天花板/窗帘，清晰、颜色也对）。

### `v4l2-ctl` 的复合读写会整条失败

一个不认识的控制名会让整个 `--set-ctrl` / `--get-ctrl` 失败。例如
`--get-ctrl=exposure,analogue_gain,digital_gain` 会返回 `unknown control 'digital_gain'`
且连 exposure 都不给。**分开写。**（`mediad::exposure` 也是因为这个分两次调用。）

### 排线朝向

Zero 3W 的 CSI 是 **22-pin 0.5mm**，不是完整树莓派的 15-pin。插反了的表现是
overlay 正常加载、IMX219 probe 失败。第一件事是拔下来换个方向，不是改配置。

### `rkaiq_3A` 和流的启动顺序

`rkaiq_3A` 必须先起来、再开始流；它在流已经跑起来之后启动会**错过 stream start 事件**，
然后永远等在那里，没有白平衡。drop-in 里用
`ExecStartPost=-systemctl --no-block try-restart mediad.service` 保证这个顺序 ——
板上没有 `mediad.service` 时这条会以 status=5 退出，是预期的。

## `mediad`：曝光闭环和网页控制台（2026-11-01 已部署）

`mediad` 接管曝光之后，**开机不再是黑图**，同时给出 `http://192.168.3.10:8080/`
的控制台网页。细节见 `REPLICA.md` §9，这里只记和摄像头直接相关的：

- 曝光：`mediad::exposure` 每 0.5 s 量一次平均亮度（目标 90），调传感器
  `exposure`（行，3000 行约 57 ms）和 `analogue_gain`（256 = 1×，上限 2816 = 11×）。
  灯太暗时会到顶，日志里是 `at_ceiling=true`、`mean_luma` 停在 70 出头。
- **`mpph264enc` / `webrtcsink` 不在默认插件路径里**，在 `/usr/local/lib/gstreamer-1.0`。
  手工 `gst-inspect-1.0` 时要 `GST_PLUGIN_PATH=/usr/local/lib/gstreamer-1.0` 前缀，
  否则会得到「插件 MISSING」的假结论（unit 里已经设了）。
- 开流时那条 `ERROR webrtcsink: Bitrate handling is not supported yet for mpph264enc`
  是**预期的**：静态码率照样生效，只是不能按拥塞反馈动态调。

`mediad` **不鉴权**且默认绑 `0.0.0.0`，只在内网用。

## 回滚

```bash
sudo cp -a /boot/extlinux/extlinux.conf.bak-20261101-212135 /boot/extlinux/extlinux.conf
sudo reboot
```

回滚后 `/dev/video*` 全部消失、dmesg 里也不再有 imx219 —— 这是去掉 overlay 的预期现象，
不是摄像头坏了。
