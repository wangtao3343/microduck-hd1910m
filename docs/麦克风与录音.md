# 麦克风与录音（TLV320AIC3104 ↔ Radxa Zero 3W）

**2026-11-02：录音、降噪、回放整条链通了。** 硬件一开始就是好的，卡住的是三件事：
增益用错（削顶听起来像"麦克风坏了"）、ADC 高通默认关、以及采集里混着数字毛刺。
本文记的是实测结论和踩过的坑；相机那套见 [摄像头接入.md](摄像头接入.md)。

## 现在的状态

| 项 | 值 |
|---|---|
| 芯片 | TLV320AIC3104（`card 1`，`plughw:aic3104,0`） |
| 麦克风输入 | **只有 `Mic3R` → `Right PGA`**，左声道恒为 **0**（不是没声音，是没接线） |
| 采集增益 | `PGA Capture Volume = 72`（36 dB，0–119，步进 0.5 dB） |
| ADC 高通 | `0.0045xFs`（48 kHz 下 216 Hz），**驱动默认是 Disabled** |
| 初始化脚本 | `/usr/local/bin/aic3104-init.sh`，由 `aic3104-init.service` 开机跑一次 |
| 录音工具 | `duck-voice`（crate `microduck/voice`），`scripts/build.sh` 一起编 |
| 播放路径 | `PCM Playback Volume 127`、`Line DAC Playback Volume 118`、`Line Playback Switch on` |

## 怎么用

```bash
# 哔一声 → 录 10 秒 → 降噪 → 放出来
~/workspace/microduck-hd1910m/out/arm64/bin/duck-voice say --seconds 10

# 只录，存文件（默认 8 秒）
duck-voice record --seconds 10 -o memo.wav

# 放一个 WAV
duck-voice play memo.wav

# 对比：不做降噪直接听原始采集
duck-voice record --raw -o raw.wav && duck-voice play raw.wav
```

`say` 前面那声哔很重要：不带口令的录音窗口，录到的是"人读操作说明时在做什么"。

## 测量结果

48 kHz、36 dB 增益、人离鸭子约 30 cm：

| 场景 | 原始 | 降噪后 |
|---|---|---|
| 正常说话（20 s，rms） | −22 ~ −31 dBFS | 同左（语音不动） |
| 说话之间的停顿 | 约 −41 dBFS | **−58 ~ −79 dBFS** |
| 安静房间、全程不说话 | **−44 dBFS** | **−59 dBFS** |
| 信噪比 | ≈ 18 dB | **≈ 35 dB** |
| 满量程毛刺 | 63 个 / 45 s | 0 |

## 坑

### 1. 削顶听起来像"麦克风坏了"

45 dB（`PGA Capture Volume 90`）下，30 cm 内正常说话峰值就顶到 32768，削掉的波形
放出来是**噼里啪啦的噪声**。第一反应往往是"麦克风噪声大"或者"麦克风坏了"，
实际是增益太大。**36 dB（72）** 是实测下来最稳的一档：人声 −17 ~ −21 dBFS，不削顶。

### 2. ADC 高通默认是关的，每次采集都带直流

`ADC HPF Cut-off = Disabled` 时录音有约 **900–1500 LSB 的直流偏置**。表现很迷惑：
把增益从 45 dB 降到 30 dB，测出来的 RMS 几乎不变——因为 RMS 被直流主导了。
设 `0.0045xFs` 后直流归零。

### 3. 采集里混着数字毛刺，不是人声

45 s 的干净录音里也能找到 **63 个单样点满量程尖峰**（±32768、<0.3 ms，左声道恒 0）。
这是采集路径的毛刺，不是声音。判别方法：真实的爆破音不会在 0.1 ms 内从房间电平跳到
±1.0 再跳回来。`dsp.rs` 里的 `despeckle` 按「远高于局部 RMS **且** 接近满量程」判定，
两个条件缺一不可——只看电平会吃掉爆破音，只看 RMS 会吃掉弱音节。

### 4. 底噪是麦克风自己的，软件消不掉

把 `Right PGA Mixer Mic3R` 关掉再录，**ADC 输出是精确的全 0**，说明噪声不是 ADC/I2S 的，
是麦克风/前级产生的。降增益只是等比例降，信噪比不变。

所以降噪能做的只有"没人说话时压下去"；**说话期间的沙沙声压不掉**（比人声低约 20 dB）。
要真正干净只有两条路：换噪声更低的麦克风，或上频谱降噪（`afftdn` 一类，代价是"水声"）。

### 5. 归一化会把静音放大回去

`clean()` 一度无条件做峰值归一化，结果**纯静音录音从 −44 dBFS 变成了 −23 dBFS**——
降噪后比原始还吵。原因：静音录音的"峰值"就是噪声本身，归一化等于把噪声门重新打开。
现在只在峰值超过 `SPEECH_PRESENT`（0.05）时才归一化，`silence_stays_silent` 这个测试守着它。

### 6. 录人声别用短窗口

`arecord -d 6` 由操作者发起、说话的人读到消息时窗口常常已经过了，录到的是纯底噪：
**稳定的 −33 dBFS、8 秒无起伏 = 没人说话**，不是麦克风坏。正确做法是先 `aplay` 一声哔作
口令，再开 **30–60 s** 的长窗口。

### 7. "录音里有测试音"不能证明麦克风在听空气

高增益下，喇叭的声音可能通过电路串扰进采集。判别方法：把 `Line Playback Switch` 关掉
（同时 `PCM Playback Volume` 归零）再放测试音，录音里还响才是串扰。本次实测关掉后
完全消失（1 kHz 幅度 19559 → 14），所以麦克风确实在听空气。

## 降噪链

`microduck/voice/src/dsp.rs`，顺序就是毛刺和噪声在信号里的顺序：

```
despeckle  →  highpass 90 Hz  →  噪声门（10 ms 帧）  →  峰值归一化（有语音时）
```

噪声门的门限不写死：取帧 RMS 的 20 分位当噪底，开到 3 倍噪底、关到 1.4 倍，
所以换房间不用改参数。开口即刻（第一个音素不能被削），关闭慢（60 ms 左右）。

## 让设置开机生效

仓库里的 `microduck/deploy/audio/aic3104-init.sh` 改了增益和高通，但板上跑的是
`/usr/local/bin/aic3104-init.sh`，**需要 root 装一次**（装完常驻，重启不用再装）：

```bash
scp microduck/deploy/audio/aic3104-init.sh duck@192.168.3.10:/tmp/
# 板上：
sudo install -m755 /tmp/aic3104-init.sh /usr/local/bin/aic3104-init.sh
```

验证（不需要重启）：

```bash
amixer -c aic3104 cget name='PGA Capture Volume'   # 应为 72,72
amixer -c aic3104 cget name='ADC HPF Cut-off'      # 应为 0.0045xFs
systemctl is-enabled aic3104-init.service          # enabled
```

## 还没做的

- **`pet-detect` 没在板上跑通过**。它用 `arecord -c 1`，而我们的麦克风只在右声道——
  `-c 1` 很可能拿到恒 0 的左声道，等于永远听不到。跑之前先验证这一点。
- 频谱降噪（`afftdn` 一类）没移植。离线实测过：只多压约 3 dB，收益不大。
- 录音目前是独立的 `duck-voice` 工具，没有接进 robotd 的 IPC（app/手柄还不能触发）。
